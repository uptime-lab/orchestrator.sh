T+0:07 The bootloader learns who to trust

What happens in those four minutes

Every step below is something the platform does and you can read back afterwards in the node's command history. The times are from one unattended run.

Measured on a Compute Module 4 with an NVMe drive on a wired network, installing Ubuntu Server 26.04 from a 1.5 GB image. A CM5 Lite did the same in 5 min 57 s.

  1. T+0:00

    Approved

    The board announced itself with its hardware serial. You said yes.

  2. T+0:07

    Bootloader signed and flashed

    The server bakes a bootloader for this one board: your public key, your server's name, a boot order that tries the network first.

  3. T+2:29

    Netbooted into recovery

    The ROM fetches a 98 MB recovery system over HTTP and refuses it unless your key signed it. It runs from RAM and touches no disk.

  4. T+3:46

    Operating system written

    The image streams from the server straight onto the drive, checksum verified. 77 seconds for Ubuntu on NVMe.

  5. T+3:50

    Agent and identity placed

    The agent package is verified against its signature and installed into the new system with this node's own credential.

  6. T+4:21

    Online, managed

    The board boots its own drive and reports in. From here it takes users, keys, software and playbooks from the server.

What you run from the server

    

      
Shell access
Declare who gets a login: users, SSH keys, sudo, certificate authorities, per node, per unit or for the whole account. A change that would lock everyone out is refused before it is sent, and again on the device.

      
OS images
Upload an image or capture a running node as a golden image, then install it on the next ten boards. Images are compressed for fast parallel installs and verified by digest.

      
Recovery
One click reboots a node into the network recovery system once, then returns it to its own disk. A root terminal in the browser works there too, on a board whose OS will not start.

      
Playbooks
A graph editor for multi-step jobs: install, wait for the node, run a script, call a webhook, branch on the result. Run them by hand or on a cron schedule across a unit.

      
Software roles
Assign Docker, a kiosk display, a VPN client, metrics or unattended security updates to a unit, and every node in it converges. Unassigning removes nothing by surprise.

      
Hardware
Watchdog, status LEDs, overclock presets, bootloader updates, carrier-board profiles. The platform knows a Compute Blade from a bare module and refuses a watchdog config that would reboot-loop the board.

      
Secrets and audit
Secrets are encrypted at rest and delivered to the nodes that need them. Every command to every device is recorded with who sent it. The trail cannot be edited through the API.

    

  






  

    
Every hop Nothing boots or installs on trust

    
Signed from the ROM to the agent

    

      
Boot ROM
Your key
The key that signs your recovery image is generated on your server and never leaves it. Each board's bootloader carries only the public half.

      
Recovery
Verified image
A board fetches the recovery system over the network and runs it only if the signature matches. A tampered image falls through to the next boot device.

      
Agent
Verified package
Agent releases are signed with offline hardware keys. The server checks a release before it stores it, and the device checks it again before it installs.

      
Server
Files, not env
Credentials reach the containers as files with tight modes. A production server refuses to start on a placeholder secret.
