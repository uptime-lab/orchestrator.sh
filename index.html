Network boot Over HTTP, from any network

No PXE. No boot server on site.

The board's own bootloader fetches a signed recovery system from the server over HTTP. An ordinary DHCP address is enough and the drive can be empty. If the server is away, the board boots its own drive.

Recovery No rescue partition

Recovery without A/B partitions

No rescue partition, no A/B scheme. A board asks the server first on every boot, so you can bring it back from the network even when its OS is completely broken. We wiped the drive of a board on the hosted service: it was back in recovery about a minute after the switch.

  1. 1

    Set the boot target

    Switch the board to Recovery in the browser.

  2. 2

    Wait a minute

    A board that cannot boot its drive keeps asking the server, so it comes back by itself. A board that hangs later needs a reboot: arm the watchdog beforehand.

  3. 3

    Fix it

    Open a root terminal, reinstall the OS or restore a backup.

What you do with it next

    

      
Users and keys
Linux users, SSH keys and sudo for one board, a unit or the whole account.

      
Images and backups
Capture a configured board as a golden image and install it on other boards. Back up a drive and restore it later.

      
Terminal and recovery
A root terminal in the browser. One click reboots a board into recovery.

      
Playbooks
Run steps on the boards you pick, by hand or on a cron schedule.

      
Managed software
Assign Docker, a kiosk display, a VPN client, metrics or security updates to a unit. Its boards keep it all installed.

      
Hardware
Watchdog, status LEDs, overclock presets, bootloader updates and carrier-board profiles, the Compute Blade included.

      
Secrets and audit
Secrets are stored encrypted. Every command is logged with its sender.

    

  






  

    
Architecture Signed from boot to agent

    
What checks what


    

      
Bootloader
Checks the recovery image
Each server has its own signing key. The bootloader refuses an image signed by another.

      
Recovery image
Carries the agent
The agent is inside the signed image.

      
Agent
Checks the OS image
The drive becomes bootable only if the SHA-256 matches.

      
Agent
Checks every package
Packages are signed on offline hardware keys. The server and the board both check them.
